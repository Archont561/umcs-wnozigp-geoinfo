## Normative status and change control

All documents begin in **Draft** status. A requirement becomes accepted only after its evidence, applicability, owner review, and associated decision are recorded. Maintain stable `SPEC-*` IDs when wording changes. Link each requirement to a backlog task and test or review evidence. Do not duplicate implementation plans in these documents; use Backlog.md tasks for execution tracking.

Backlog document IDs (`doc-*`) are generated by Backlog.md and may change only through its document-management commands; the stable product-specification IDs are the `SPEC-*` identifiers in each heading. List the entries with `pixi run --locked bunx --no-install backlog doc list --plain`.
